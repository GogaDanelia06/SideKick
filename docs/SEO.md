# SEO — რა გაკეთდა Sidekick-ზე

ეს დოკუმენტი აღწერს საიტის SEO-ს მდგომარეობას: რა არის უკვე გაკეთებული, რა
იმართება ადმინ პანელიდან და რა რჩება ჩასართავად.

---

## 1. მოკლედ

SEO სამ ფენად აეწყო:

| ფენა | სად ცხოვრობს | ვინ ცვლის |
| --- | --- | --- |
| **გლობალური** — საიტის სახელი, ორგანიზაცია, ნაგულისხმევი სურათი, ენა | `seo.config.json` ფაილი | დეველოპერი (pull request-ით) |
| **გვერდის** — სათაური, აღწერა, canonical, index/noindex, OG | ბაზა (`PageSeo`) | **ადმინი, პანელიდან** |
| **ტექნიკური** — sitemap, robots.txt, სქემები, lastmod | კოდი, ავტომატური | არავინ — თავისით მუშაობს |

ეს დაყოფა განზრახია. ის, რაც წელიწადში ერთხელ იცვლება და შეცდომისას საიტს
ძებნიდან აგდებს (მაგ. canonical დომენი), ფაილშია და კოდის განხილვას გადის.
ის, რაც ხშირად იცვლება, ადმინშია.

---

## 2. თითოეული გვერდი

შვიდივე საჯარო გვერდს აქვს სრული SEO:

| გვერდი | სქემები |
| --- | --- |
| მთავარი `/` | Organization · WebSite · WebPage · **SoftwareApplication** (ფასების დიაპაზონით) |
| ფასები `/pricing` | + SoftwareApplication · BreadcrumbList |
| ჩვენ შესახებ `/about` | **AboutPage** · BreadcrumbList |
| კონტაქტი `/contact` | **ContactPage** · **FAQPage** · BreadcrumbList |
| წესები `/terms` | WebPage · BreadcrumbList |
| კონფიდენციალურობა `/privacy` | WebPage · BreadcrumbList |
| მონაცემთა დაცვა `/data-protection` | WebPage · BreadcrumbList |

ყველა გვერდზე: Meta Title, Meta Description, H1, Canonical, Index/Noindex,
OG Title/Description/Image, Twitter Card.

### სათაურების იერარქია

თითო გვერდზე **ზუსტად ერთი H1**, შემდეგ H2 და H3. მთავარ გვერდზე H1 არის
კარუსელის სლაიდის სათაური.

---

## 3. რა იმართება ადმინ პანელიდან

**ადმინი → [გვერდი] → SEO** — თითოეულ გვერდს თავისი აქვს.

| ველი | |
| --- | --- |
| Meta Title | ✅ |
| Meta Description | ✅ |
| **H1** | ✅ — გვერდის კონტენტის სექციაში |
| Canonical URL | ✅ |
| Index / Noindex | ✅ ღილაკით |
| OG Title / Description / Image | ✅ |
| Slug (მისამართი) | ❌ — იხ. ქვემოთ |

**ცარიელი ველი ნიშნავს „გამოიყენე ნაგულისხმევი".** ველის დაცარიელება
ჩაშენებულ მნიშვნელობას აბრუნებს და არა ცარიელ ტეგს — ცარიელი
`<meta content="">` უარესია, ვიდრე ტეგის არქონა. ველში placeholder-ად სწორედ
ის ჩანს, რაც ნაგულისხმევად გამოვა.

### რატომ არ იმართება Slug

მისამართები Next.js-ის ფაილურ სტრუქტურაშია განსაზღვრული — `/pricing` არის
საქაღალდის სახელი კოდში. ადმინში ველი ჩანს, მაგრამ გამორთულია და მიწერილი
აქვს, რომ შეცვლა დეველოპერს სჭირდება.

ცარიელი ველი, რომელიც არაფერს არ აკეთებს, უფრო დამაბნეველი იქნებოდა.

---

## 4. გლობალური პარამეტრები

ფაილი `seo.config.json` პროექტის ძირში. თოთხმეტი პარამეტრი, ოთხ ბლოკად:

- **website** — სახელი, მისამართი, სათაური, აღწერა
- **organization** — სახელი, იურიდიული სახელი, ლოგო, ელფოსტა, ტელეფონი,
  მისამართი, სოციალური ქსელები
- **defaults** — OG სურათი, ენა, locale, canonical დომენი
- **analytics** — Google Analytics / Tag Manager / Facebook Pixel
- **verification** — Google, Bing, Yandex, Facebook

**ცარიელი ველი საერთოდ არ იბეჭდება.** სანამ ანალიტიკის ID ცარიელია, არც ერთი
მესამე მხარის სკრიპტი არ იტვირთება.

⚠️ ანალიტიკის ჩართვისას CSP-ს შეცვლა სჭირდება — `next.config.ts`-ში კომენტარად
ზუსტად წერია, რომელი ხაზები დაემატოს. მის გარეშე ბრაუზერი სკრიპტს დაბლოკავს.

## 5. ტექნიკური ნაწილი

### Sitemap

`/sitemap.xml` — ყოველი მოთხოვნისას იგება ბაზიდან.

**`lastmod` რეალურია.** თითოეული გვერდის თარიღი მისივე კონტენტის ბოლო
რედაქტირების მომენტია, არა build-ის დრო. ეს მნიშვნელოვანია: build-ის თარიღი
Google-ს ეუბნებოდა, რომ ყოველ deploy-ზე ყველა გვერდი შეიცვალა — ასეთ სიგნალს
Google სწრაფად სწავლობს და იგნორირებას უწყებს.

**Noindex გვერდი sitemap-ში არ ხვდება.** გვერდის ჩამოთვლა და ამავე დროს
„არ დაინდექსო" ურთიერთგამომრიცხავია და Search Console-ში შეცდომად ჩანს.

### robots.txt

დახურულია: `/dashboard`, `/admin`, `/api`, `/login`, `/register`, `/forgot`,
`/reset`, `/start`. Sitemap-ის მისამართი მითითებულია.

### სტრუქტურირებული მონაცემები (JSON-LD)

Organization, WebSite, WebPage, AboutPage, ContactPage, SoftwareApplication,
FAQPage, BreadcrumbList.

გადამოწმება: [Google Rich Results Test](https://search.google.com/test/rich-results).

## 6. რა რჩება

| | ვის ეკუთვნის |
| --- | --- |
| Google Search Console-ში რეგისტრაცია + verification ტოკენი | კლიენტი |
| Bing Webmaster Tools (Search Console-იდან იმპორტით) | კლიენტი |
| `sidekick.ge` დომენის ჩართვა | კლიენტი |
| ორგანიზაციის მისამართი/ტელეფონი კონფიგში | კლიენტი |

⚠️ **დომენის ჩართვისას აუცილებლად შეიცვალოს `NEXT_PUBLIC_SITE_URL`** — canonical
და OG მისამართები მისგან იგება. თუ არ შეიცვლება, Google-ს ძველ მისამართს
ვეტყვით.

⚠️ **Search Console-ში რეგისტრაცია დომენის ჩართვის შემდეგ ჯობს** — თორემ Vercel-ის
დროებით მისამართს დაარეგისტრირებთ და თავიდან მოგიწევთ.

### Google Indexing API — არ გამოგვადგება

მოთხოვნილი იყო, მაგრამ Google-ის Indexing API **მხოლოდ ორი ტიპის გვერდისთვისაა
დაშვებული**: `JobPosting` (ვაკანსიები) და `BroadcastEvent` (ვიდეო-ტრანსლაციები).
Sidekick-ს არც ერთი აქვს — Google უბრალოდ იგნორირებას გაუკეთებდა ჩვენს
მოთხოვნებს.

სამაგიეროდ არსებობს: sitemap-ის `lastmod` (გაკეთებულია), Search Console-ის
URL Inspection, და Bing/Yandex-ის IndexNow პროტოკოლი, რომელიც ნებისმიერ გვერდზე
მუშაობს.
